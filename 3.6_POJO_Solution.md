## Key concepts used in this section

Before looking at the code, here are three terms you will need.

### Pass by value

When you pass a **primitive** such as `int` or `double` to a method, Java copies the value. The method gets its own copy, so changing it inside the method has no effect on your variable.

```java
public static void change(int number) {
    number = 999;
}

int x = 10;
change(x);
System.out.println(x);   // still 10
```

### Pass by reference (what actually happens with objects)

Java is always technically pass by value, but when you pass an **object**, the value being copied is the **reference**, the address that points to the object.

So the method does not get a copy of your object. It gets a second pointer to the *same* object. Two names, one object in memory.

That means if the method changes the object, you see the change, because there is only one object.

```java
public static void change(OrderItem item) {
    item.setAmount(0);
}

OrderItem laptop = new OrderItem("Laptop", 1200.00);
change(laptop);
System.out.println(laptop.getAmount());   // 0.0, our object changed
```

The same applies to collections. A `List` is an object, so passing a list hands the method your actual list.

### Defensive copy

A defensive copy means creating a genuinely new object or collection before working with it, so the original stays safe.

```java
List<OrderItem> copy = new ArrayList<>(original);
```

This builds a brand new list. Adding to it or clearing it does not touch the original.

You will use defensive copies in three places:

1. When a method receives a collection it should not modify
2. When a getter returns a collection field
3. When a constructor accepts a collection

## The POJO: OrderItem

```java
public class OrderItem {

    private String productName;
    private double amount;

    public OrderItem() {
    }

    public OrderItem(String productName, double amount) {
        this.productName = productName;
        this.amount = amount;
    }

    public String getProductName() {
        return productName;
    }

    public void setProductName(String productName) {
        this.productName = productName;
    }

    public double getAmount() {
        return amount;
    }

    public void setAmount(double amount) {
        this.amount = amount;
    }

    @Override
    public String toString() {
        return "OrderItem [productName=" + productName + ", amount=" + amount + "]";
    }
}
```

> **Note:** Without the `toString()` override, printing a list of these shows hashcodes such as `[OrderItem@1b6d3, OrderItem@4a3f8]`. Every POJO you write needs its own `toString()`. It is not inherited from anywhere useful.

## Using the POJO in a collection

```java
import java.util.ArrayList;
import java.util.List;

public class App {
    public static void main(String[] args) {

        List<OrderItem> items = new ArrayList<>();
        items.add(new OrderItem("Laptop", 1200.00));
        items.add(new OrderItem("Monitor", 350.00));

        System.out.println(items);
    }
}
```

**Output:**

```bash
[OrderItem [productName=Laptop, amount=1200.0], OrderItem [productName=Monitor, amount=350.0]]
```

> **Note:** A `List<OrderItem>` does not store the objects themselves. It stores references to them. That is why the same `OrderItem` object can appear in two different lists, and changing it changes what both lists show.

## Run 1: Passing the list to a method

```java
import java.util.ArrayList;
import java.util.List;

public class App {

    public static void main(String[] args) {

        List<OrderItem> items = new ArrayList<>();
        items.add(new OrderItem("Laptop", 1200.00));
        items.add(new OrderItem("Monitor", 350.00));

        System.out.println("Before: " + items);

        processOrders(items);

        System.out.println("After: " + items);
    }

    public static void processOrders(List<OrderItem> orders) {

        for (OrderItem item : orders) {
            // business logic here
        }

        orders.clear();
    }
}
```

**Output:**

```bash
Before: [OrderItem [productName=Laptop, amount=1200.0], OrderItem [productName=Monitor, amount=350.0]]
After: []
```

Your list is now empty. You never called `clear()` in `main` and you never assigned anything back. All you did was pass the list into a method.

> **Note:** This is pass by reference in action. `orders` inside the method and `items` in `main` are two names for the same list. There is only one list, so whatever the method does to it is permanent.

## Run 2: The defensive copy

Change only the method. Everything else stays the same.

```java
    public static void processOrders(List<OrderItem> orders) {

        List<OrderItem> workingCopy = new ArrayList<>(orders);

        for (OrderItem item : workingCopy) {
            // business logic here
        }

        workingCopy.clear();
    }
```

**Output:**

```bash
Before: [OrderItem [productName=Laptop, amount=1200.0], OrderItem [productName=Monitor, amount=350.0]]
After: [OrderItem [productName=Laptop, amount=1200.0], OrderItem [productName=Monitor, amount=350.0]]
```

The original list survives, because `new ArrayList<>(orders)` builds a genuinely new list for the method to work on.

> **Note:** Same method name, same line of code where you call it, opposite outcome. Nothing at the call site tells you which version you are getting. This is why passing collections around is a common source of bugs in real projects, and why defensive copying is worth the extra line.

## The same thing with a single object

You do not need a collection to see this.

```java
    public static void applyPromotion(OrderItem item) {
        item.setAmount(0);
    }
```

```java
        OrderItem laptop = new OrderItem("Laptop", 1200.00);
        System.out.println("Before: " + laptop);

        applyPromotion(laptop);

        System.out.println("After: " + laptop);
```

**Output:**

```bash
Before: OrderItem [productName=Laptop, amount=1200.0]
After: OrderItem [productName=Laptop, amount=0.0]
```

You passed the object in, you never reassigned anything, and your object changed.

> **Note:** This is why a getter should return a copy rather than the raw collection, and why a copy constructor should copy a collection rather than assign it. Once a field holds a reference to something changeable, making it private is not enough. You also have to control who gets hold of the reference.

## Going one level deeper: the copy is shallow

```java
        List<OrderItem> copy = new ArrayList<>(items);
        copy.get(0).setAmount(999.00);
        System.out.println(items);   // the original shows 999.0 too
```

> **Note:** `new ArrayList<>(items)` creates a new **list**, but that new list holds the **same** `OrderItem` objects. So clearing the copy is safe, but changing an item inside it still affects the original. This is the difference between a shallow copy and a deep copy. A deep copy would mean creating a new `OrderItem` for each element as well, which is rarely needed in practice but worth knowing about.
